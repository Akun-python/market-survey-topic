# SK1 背景分析：把"为什么要研究"写成可验证的论证

> **一句话**：研究背景不是"政策好、市场大、前景广阔"的抒情，而是「**政策在推 + 市场在变 + 学术有缺口 → 所以我来补这个缺口**」的论证链。

## 一、定位与适用场景

- **用在报告哪里**：第一章绪论（1.1 研究背景 / 1.2 研究意义 / 1.3 研究目的 / 1.4 研究创新点）。
- **用在什么阶段**：选题立项、企业命题本地化、报告开写前的"背景定型"。
- **不适用**：纯方法练习、无调研对象的数据复现；这类场景跳过本节直接进 SK2。

## 二、输入清单（缺一项先补齐再动笔）

| 输入 | 具体要求 | 来源 |
|---|---|---|
| 选题卡 | 研究对象 + 两个研究点 + 拟调研地区 | 本仓库选题库（`_industry_map.json` + 行业 README） |
| 政策文件 | ≥3 份，含**发文机关 + 年份 + 文件名** | 政府官网、地方政府工作报告、北大法宝 |
| 行业数据 | 规模 / 增速 / 渗透率 ≥3 个，带年份 | 国家统计局、行业协会、第三方报告（🔶 须核原文） |
| 文献 | 近 5 年 ≥15 篇（含 2–3 篇外文） | 知网、万方、Web of Science |
| 舆情快照（可选） | 百度指数、微博/小红书热帖 | 平台公开数据 |
| 避重核验 | 近三年获奖名单 | `../../references/获奖名单/` |

## 三、标准步骤

### 第 1 步｜政策线（约占本章 30%）
检索公式：`<核心词> + 政策 / 规划 / 条例 / 意见 / 行动方案`。按时间排 3–6 条，做成**政策时间线表**：

| 时间 | 发文机关 | 文件 | 关键要点 | 与本题关系 |
|---|---|---|---|---|
| 2021.09 | 〔省〕人大 | 《〔对象〕发展条例》 | 〔关键条款 + 量化目标〕 | 证明政策强推 → 居民认知与意愿值得测 |
| … | … | … | … | … |

> 常见做法：政策按"国家 → 省 → 市"三层递进（只写中央不写地方 = 没本地化），每行点出与本题关系；试点/补贴类通知可另附截图并标注出处。

### 第 2 步｜市场线（约 25%）
回答三问，每问必须有数字：
1. **市场多大**：规模/用户数/销售额（给年份与来源）；
2. **增长多快**：CAGR 或同比增速；
3. **痛点在哪**：供给不足 / 需求未被满足 / 认知错位 / 价格与体验矛盾。

❌ 禁止出现"前景广阔""潜力巨大"却没有任何数字。

### 第 3 步｜技术与行业线（约 10%，可选）
技术演进或产业阶段，配 1 个落地案例（示范项目、头部企业布局、技术突破）。常见写法：分类列举技术 + 成熟度，或按"萌芽—成长—爆发"说清产业所处阶段。

### 第 4 步｜学术线（约 35%，最关键）
文献综述按「**现状 — 争议 — 缺口**」三段组织，每段 3–5 篇：
1. **现状**：别人研究了什么（研究对象 / 方法 / 结论各一行）；
2. **争议**：结论不一致，或方法有局限；
3. **缺口**：一句话落到本文两个研究点——
   > "已有研究集中于 A；但对 B 关注不足；本文以 C 为切口补足。"

> 常见做法：综述分 2–3 个小节（现状/争议/缺口），末段明确"鲜有对〔使用者/某群体〕的调查"；同时交代本文要用到的理论（如技术接受、源可信性、态度中介模型），让文献在方法与假设处被实际引用。

### 第 5 步｜研究意义（理论 + 实践）
- **理论**：补哪个缺口、对哪类研究有增量（1–2 句）；
- **实践**：对政府 / 企业 / 消费者分别有什么用（各 1 句，落到"可用于什么决策"）。

### 第 6 步｜研究目的（≤3 条）
每条 = **动词 + 对象 + 产出**，且与后文章节一一对应。
常见落点：现状认知 / 影响因素与机制 / 预测或对策建议。

### 第 7 步｜研究创新点（3–4 条）
统一句式：**"别人做了 X，我们做 Y（且可验证）"**。可覆盖四个角度：
- 热点创新（选题新）
- 内容创新（研究对象/视角新）
- 方法创新（如机器学习组合、文本挖掘、扎根理论 + 深度学习）
- 视角创新（如聚焦目标受众中的"非用户"群体）

### 第 8 步｜自检
按第六节清单逐条打勾。

## 四、方法与模板

**文献矩阵**（防"堆砌式综述"）：

| 文献（作者, 年份） | 对象 | 方法 | 结论 | 局限 | 本文承接 |
|---|---|---|---|---|---|

**缺口三段式模板**：

> 已有研究主要集中在〔A：现象/技术/政策〕层面；对〔B：用户视角/异质性/新场景〕关注不足，且〔C：方法局限——样本单一、横截面、未控制某变量〕；本文将〔D：两个研究点〕作为切口，采用〔E：方法组合〕补足这一缺口。

**字数结构**（总 1500–2500 字，第一章 4–6 页）：政策 30% / 市场 25% / 技术 10% / 学术 35%。

## 五、产出模板（可直接改写的骨架）

```markdown
## 第一章 绪论
### 1.1 研究背景
#### 1.1.1 政策背景：〔国家〕+〔省〕双线推进
（政策时间线表 + 2 段解读）
#### 1.1.2 市场背景：〔规模〕到〔增速〕，痛点在〔某环节〕
（3 个数据 + 1 个痛点）
#### 1.1.3 学术背景：已有研究到这里，缺的是〔缺口〕
（现状 → 争议 → 缺口三段，末句引出本文）
### 1.2 研究意义
（理论 1 段 + 实践 3 个主体各 1 句）
### 1.3 研究目的
（3 条，与第四/五/六章对应）
### 1.4 研究创新点
（3–4 条，每条"别人 X，我们 Y"）
```

## 六、验收标准（逐条打勾）

- [ ] 政策 ≥3 条，且含发文机关 + 年份 + 文件名
- [ ] 市场数据 ≥3 个，均标注来源与年份；🔶 类已下载原文核对
- [ ] 文献 ≥15 篇、近 5 年为主，综述按"现状—争议—缺口"组织
- [ ] 缺口落到本文两个研究点，并与后文假设/问卷维度对应
- [ ] 研究意义分理论/实践，实践指向具体主体
- [ ] 研究目的 ≤3 条，与章节一一对应
- [ ] 创新点 3–4 条，不出现无依据的"首次/填补空白"
- [ ] 引用格式统一（GB/T 7714），正文引用与文末参考文献一一对应

## 七、报告呈现要求

- 位置：第一章；篇幅 **4–6 页**（在正文页数预算内；当前赛制为正文 ≤65 页，以当届要求为准）
- 可配：政策时间线表（表 1 或图 1）、市场规模趋势图（图 1）
- 文献综述篇幅 ≤ 本章 40%；每段开头用一句话概括，避免长段落
- 图/表编号与全文连续（图 1 起、表 1 起）

## 八、常见坑

1. **只有背景没有"问题"**：读完不知道你要解决什么 → 用缺口句收尾。
2. **政策不本地化**：只写中央、不写省/市 → 至少补省级 1 条、市级 1 条。
3. **文献堆砌不批判**：罗列 20 篇没有"所以呢" → 每段末尾加"这提示……"。
4. **缺口与后文脱节**：缺口说"缺用户视角"，问卷却只问政策 → 做映射。
5. **创新点与内容无关**：创新点写了"方法创新"，正文却无该方法 → 删或补。
6. **🔶 数据未核原文**：行业报告线索直接引用 = 评审重点扣分。
7. **大段复制政策原文**：查重风险 → 转述 + 引用。

## 九、开源工具链（完整命令见 `OPEN_SOURCE_STACK.md`）

- **文献管理**：Zotero（开源）+ Better BibTeX 插件，管理 ≥15 篇文献并一键导出 GB/T 7714 条目；
- **检索补充**：OpenAlex / Crossref API（开源学术数据）补充外文文献线索；
- **政策与数据核对**：政府官网 + 统计年鉴；行业线索（🔶）用 Python `requests` 抓官网原文再人工核对；
- **写作**：Markdown 成稿，Pandoc/Quarto 统一排版（与 SK6 共用）。

## 十、写法要点（对照历届获奖作品自检）

高分作品的绪论通常具备以下特征，可凭此自查差距：

1. 政策时间线表（国家 → 省 → 市三层）+ 每行"与本题关系"列；
2. 市场数据 ≥3 个、带年份与来源，痛点一句话说清；
3. 综述按"现状—争议—缺口"组织，缺口句直接落到本文两个研究点；
4. 文献在方法与假设处被实际引用（不是只在综述出现一次）；
5. 意义分理论/实践，实践落到具体决策主体；
6. 目的 3 条、创新点 3–4 条，全部在后文有对应；
7. 引用 GB/T 7714，正文引用与文末一一对应。
