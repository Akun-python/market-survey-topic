# SK8 结论撰写：结论要"扎在数据上"，建议要"落在地上"

> **一句话**：结论 = **发现 + 证据 + 解释**；建议 = **主体 × 动作 × 落地路径 × 依据**。每条建议必须能回指一条结论，每条结论必须能回指一张图表。

## 一、定位与适用场景

- **用在报告哪里**：倒数第二章"结论与建议"。
- **用在什么阶段**：SK4 分析完成、结论—证据链表就绪后；建议要结合背景与文献补论证。
- **不适用**：数据尚在返工时不要写结论（会反复推翻）。

## 二、输入清单

| 输入 | 来源 |
|---|---|
| 结论—证据链表 | SK4 产出（结论 ↔ 图表号 ↔ 统计量/p） |
| 假设检验结果 | SK4 建模输出（H1–H4 支持/不支持） |
| 背景与文献 | SK1 产出（建议的论证依据） |
| 画像与异质性结果 | SK4-L3（"对哪类人有效"是建议的抓手） |

## 三、标准步骤

### 第 1 步｜写结论（4–7 条，按研究问题编号）

每条三段式：
1. **发现句（结论化）**："〔群体〕的〔变量〕显著〔高于/低于/正相关/影响〕……"；
2. **数据证据**：括号标注"（图 X/表 X；系数 β=…，p<0.05）"；
3. **一句解释**：为什么出现这个结果（理论/常识/对比文献）。

> 反例："通过分析发现，受访者认知程度一般。"——这不是结论，是描述。
> 正例："男性对〔对象〕的认知度显著高于女性（χ²=…, p<0.05，表 18），可能与男性对工程类信息关注度更高有关。"

### 第 2 步｜选建议组织方式（二选一，全章统一）

**方式 A｜主体分层式**：政府 / 行业部门 / 企业 / 社区 / 个人（或政府 / 机构两类主体）。
**方式 B｜策略主题式**：破圈 / 精准营销 / 谨慎选人 / 满足需求 / 渠道 / 内容。

每条建议四要素：
- **主体**：谁来做（部门/企业/机构/个人）；
- **动作**：动词开头（建立/完善/简化/加强/引导）；
- **落地路径**：通过什么抓手、什么渠道、什么机制；
- **依据与预期**：对应结论编号 + 预期效果。

> 反例："政府应加强宣传。"——主体有了，但抓手、对象、渠道全无。
> 正例："政府应联合〔机构〕在各乡镇开展〔主题〕培训讲座（依据结论 2），提升〔群体〕风险防范意识；并将〔补贴〕与〔保费补贴〕结合，降低参保门槛。"

### 第 3 步｜建映射表（防"建议跑偏"）

| 结论编号 | 结论摘要 | 证据（图表/检验） | 建议编号 | 主体 | 动作与抓手 |
|---|---|---|---|---|---|
| 1 | 认知存在性别/年龄差异 | 表 18–25 | 建议 2 | 社区 | 针对低认知群体开展培训… |

### 第 4 步｜可选：局限与展望（2–3 条）
- 样本局限（单一城市/横截面）；
- 方法局限（自报数据/未做实验）；
- 展望（纵向追踪、扩大地区、引入实验方法）。

## 四、结论与建议的组织方式对照

| 组织方式 | 结论组织 | 建议组织 | 适用与要点 |
|---|---|---|---|
| 按研究链分节 | 认知/意愿/支付/前景各一小节 | 按主体分列（政府/部门/企业/社区/个人） | 结论与章节一一对应；建议每主体 2–3 条，含"做什么 + 为什么" |
| 编号结论式 | 5–7 条编号结论，每条带数字 | 策略主题 5–8 条 | 结论与建议均行动导向，每条对应一条发现 |
| 双层结构 | 先总后分或按维度分节 | 单产品/单对象建议 + 产业/行业建议 | 适合产品类选题；行业层建议可加 4–6 条 |
| 阶段化 | 按消费者旅程/阶段分节 | 激活/转化/留存或分阶段策略 | 适合营销类选题，建议与模型环节一一对应 |

**共性**：结论带方向与数字；建议按责任主体或策略主题分列，可执行、可考核。

## 五、写作模板

```markdown
## 结论与建议
### 一、研究结论
1. 〔发现 + 证据（图/表/系数/p）+ 解释〕
2. ……
### 二、对策建议
#### （一）政府层面
1. 〔动作 + 抓手 + 依据（结论 x）+ 预期效果〕
#### （二）企业层面
……
### 三、研究局限与展望（可选）
```

## 六、验收标准（逐条打勾）

- [ ] 结论 4–7 条，按研究问题编号，每条含"发现 + 证据 + 解释"
- [ ] 结论回应标题/引言提出的**每个**研究点（一个不漏）
- [ ] 每条结论可回指具体图表或检验（映射表非空）
- [ ] 建议 ≥3 类主体（或 ≥4 条策略），每条含主体 + 动作 + 抓手
- [ ] 每条建议映射到 ≥1 条结论（无"凭空建议"）
- [ ] 无"加强宣传/提高认识"式空话（须给渠道、对象、机制）
- [ ] 建议可考核（有抓手、可执行，不是口号）
- [ ] 数字与正文、摘要一致；不出现未验证数据
- [ ] 无过度承诺（"必将普及""彻底解决"）

## 七、常见坑

1. **结论复述"结果"**：把描述统计再写一遍 → 要做"结论化"提炼。
2. **结论与假设脱节**：假设 H3 未支持，结论却写"支持"。
3. **建议不分主体**：一段话建议所有人 → 无法落地。
4. **建议与研究结论无关**：结论说价格敏感，建议只谈宣传。
5. **空话建议**：无主体/无抓手/无预期。
6. **结论过多**：12 条流水账 → 收敛到 4–7 条，其余进正文。
7. **忽略反面结果**：负面情绪/不支持假设隐去 → 评委会扣"结论严谨性"。
8. **局限不写或用"时间有限"敷衍**。

## 八、开源工具链（完整命令见 `OPEN_SOURCE_STACK.md`）

- **映射表**：用 `pandas`/Excel 生成"结论-建议-证据"对账表，交付前逐行核对（每个建议回指 ≥1 条结论）；
- **SWOT/策略图**：draw.io（开源）画 SWOT 矩阵与策略路径图（评审易读，建议配一张）；
- **可操作性预检（辅助）**：脚本扫描建议条目是否含"主体 + 动词 + 抓手"，缺失则标黄人工补写（非替代人工判断）；
- **建议数字化**：每条建议尽量带一个可考核目标（覆盖率/满意度提升幅度等），出图用 SK5 规范。

## 九、写法要点（对照历届获奖作品自检）

高分作品的结论与建议章节通常具备以下特征：

1. 结论 4–7 条，每条"发现 + 证据 + 解释"，与假设逐条对应（未支持也如实写）；
2. 结论按研究链分节或编号，能回指具体图表与检验；
3. 建议主体明确（政府/企业/社区/个人，或策略主题），每条有抓手、可考核；
4. 每条建议都能映射到一条结论（另附映射表对账）；
5. 常见组织：SWOT → 策略、阶段化（激活/创收/留存）、单产品 + 产业双层；
6. 无"加强宣传/提高认识"式空话，无过度承诺；局限与展望 2–3 条（可选）。
