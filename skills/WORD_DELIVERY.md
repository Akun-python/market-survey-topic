# Skill 成果的 Word（DOCX）交付规范

本规范供 `skills/` 下每个 Skill 共用。每个 Skill 必须产出一个可单独阅读、可编辑、可交付的完整 `.docx` 阶段成果；只有 Markdown 片段、代码、图表图片或模板不算完成。阶段成果不等于整份竞赛报告：例如问卷 Skill 交付完整问卷文件，数据分析 Skill 交付完整分析章节文件。

## 一、每份 DOCX 的基本组成

1. **标题页/文档首页**：成果名称、研究题目、地区/对象、团队或作者（缺失时留占位符）、版本/日期、状态（草稿/待核验/定稿）。短小附件如问卷、摘要可用规范标题页眉代替独立封面，但须含题目和版本。
2. **正文主体**：按对应 Skill 产出大纲完整写成文档，不允许仅给空白大纲、目录或“待补内容”。真实信息缺失时用清晰标注的 `[待补：...]` / `[待核验：...]`，同时列入待办。
3. **必要图表/附表/附录**：图表须嵌入 Word 或作为对应文档中的完整可读表格；不能只给文件路径。问卷全文、核心计算表、必要方法/变量说明等按本 Skill 要求附入。
4. **来源与说明**：引用处有编号或作者-年份标记，文末列参考来源；数据、政策、图片、量表和外部材料都标出处。未能核验的来源注明“待核验”，禁止编造。
5. **文末质检页/清单**：记录内容缺口、假设、版本和检查结果。依赖团队实证数据的阶段不得虚构结果；没有数据时交付设计/占位版并明确禁止作为实证定稿。

## 二、统一 Word 样式

- 页面按当届官方模板优先；无模板时用 A4、纵向、常规页边距（上下约 2.54 cm，左右约 3.0 cm）。横向宽表可单页横向节，不得缩到难读。
- 使用 Word 内置标题样式（Title、Heading 1–3）、正文样式、自动页码；目录使用可更新的自动目录字段。不要靠手打空格、回车或下划线排版。
- 正文建议中文宋体/等效中文字体 10.5–12 pt，标题层级清晰；行距、段距一致。提交前确认字体可用，避免缺字或乱码。
- 表格使用统一表头、单位、注释和来源行；长表重复表头，单元格不截断。图片清晰并带编号、标题、图注和来源；建议≥300 dpi。公式使用可编辑公式或清楚排版的文本，并定义符号。
- 参考文献按当届要求；无特别规定时统一 GB/T 7714。正文引文与文末条目一一对应。
- 正文、摘要和附录页数/字数以当届官方要求为准；不得把本 Skill 的建议口径冒充官方规定。

## 三、生成与验证流程

1. 先依据相应 Skill 的输出大纲完成内容和来源清单，再生成 DOCX；只把已核实的数字作为事实。
2. 推荐使用 `python-docx` 生成可编辑文档。仓库工具总纲提供 Python 环境与示例；亦可用 Word/LibreOffice 手工排版。内容应可追溯，不把图表或结论截图替代可编辑正文。
3. 保存有描述性的文件名，例如 `研究题目_选题推荐_日期.docx`、`研究题目_研究设计.docx`，不要覆盖原始数据或用户文件。
4. 用 LibreOffice/Word 打开或无界面转换 PDF，检查页数、分页、表格溢出、图片缺失、字体乱码、目录/页码、超链接和公式；DOCX 至少要能成功重新打开/转换。
5. 将 DOCX 交付路径写入最终回复，并说明是草稿、待核验稿还是定稿；同时交付必要的可编辑数据/脚本/图片素材，但不能只交这些素材而漏掉 DOCX。

## 四、自动生成的最低技术检查

Python 可用 `python-docx` 设置 `Document()`、页面尺寸与边距、`Normal`/标题样式、页眉页脚和页码字段，按层级添加段落、表格及图片，最后 `save(path)`。生成后至少验证：

- 文件存在且大小合理；
- `python-docx` 能重新打开，标题、段落、表格数非零且正文不是空壳；
- 所有必需章节、待核验项和来源清单存在；
- 若包含图表，图片关系正常、替代文本/图注存在；
- 用 Word/LibreOffice 实际渲染后无截断、空白页或乱码。

> 这个规范保证交付物完整、可打开、可编辑，不保证研究结论正确；研究质量仍须通过各 Skill 的领域验收清单和人工核验。
